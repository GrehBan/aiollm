# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`aiollm` is a pre-alpha (0.14.0), async-first, low-level toolkit for building typed HTTP API clients, aimed at AI providers. It ships the infrastructure, `OpenAIClient` (OpenAI's Responses and Files APIs) and `AnthropicClient` (Anthropic's Messages and Files APIs), both with the provider-neutral `client.generation` and `client.files`. The public surface is unstable.

**The code says what the library does; an agreed decision says what it should do.** This file, the README and the site describe the code and may lag. When they disagree, find the cause: a text that lags behind the code is fixed; code that contradicts an agreed decision is a bug, raised with the maintainer, never settled by declaring the code right. `CONTRIBUTING.md` (also the site's Contributing page) is the guide for contributors, with directives for those who work with Claude; keep it in step with this file. The user documentation is the MkDocs site in `docs/` (published at <https://aiollm-org.github.io/aiollm/>); its reference pages are generated from the docstrings, so a docstring is user documentation too.

## Commands

The project is managed with `uv` (see `uv.lock`) and requires Python 3.13 or newer (`.python-version` pins 3.13, the oldest supported version, so local runs and CI catch newer syntax). The version is read by hatchling from `src/aiollm/__meta__.py`.

```bash
uv sync --all-groups                 # install runtime + dev + test + docs deps
uv run ruff check src tests          # lint (line length 79)
uv run ruff format src tests         # format
uv run mypy src                      # strict type checking (pydantic.mypy plugin)
uv run pyright                       # strict pyright over src and tests
uv run pytest                        # tests (testpaths = tests, asyncio_mode = auto)
uv run pytest tests/path/test_x.py::test_name   # single test
uv run pytest --cov                  # with coverage (branch, fail_under = 98)
uv run pytest --mypy -m mypy tests/typing       # static checks of the public API
uv run mkdocs serve                  # the docs site at http://127.0.0.1:8000
uv run mkdocs build --strict         # build it; any warning fails
uv run rumdl check README.md CHANGELOG.md CONTRIBUTING.md docs   # Markdown lint
uv run pre-commit install            # once: hooks from .pre-commit-config.yaml
uv run towncrier create +slug.fixed.md   # a changelog fragment in CHANGES/
uv run towncrier build --draft       # preview the next CHANGELOG section
uv run python scripts/generate_provider_types.py  # provider types and request params (pinned generator and inputs)
uv run python scripts/refresh_upstream.py        # move the schema pins to upstream, rebuild snapshot and types
```

CI (`.github/workflows/tests.yml`) runs the checks, the Markdown lint, `mkdocs build --strict` and a regeneration of the provider types that must change no file (job `lint and types`), pytest on Ubuntu and Windows × every supported CPython (3.13, 3.14, 3.15; the `tests` job sums up the matrix, so the branch ruleset needs one stable name), a wheel built and imported in a clean environment (`package`), `uv audit` of the lockfile (`audit`) and, on pull requests, `towncrier check` (`changelog`: a PR adds a fragment to `CHANGES/` or changes `CHANGELOG.md`; the `no changelog` label skips it); `.github/workflows/docs.yml` publishes the site to GitHub Pages on every push to `master`; `.github/workflows/upstream.yml` runs `scripts/refresh_upstream.py` every Monday (and by hand): a schema source ahead of its pin (the newest commit of OpenAI's `openapi.yaml`, the newest `anthropic` on PyPI) becomes one pull request on `upstream/refresh`, opened with the `UPSTREAM_PR_TOKEN` secret so CI runs on it, with the moved pins, the rebuilt snapshot and the regenerated types, and lists in its body the public names they add or remove against `tests/unit/public_api.json` (updated by hand); once a commit was pushed to that open pull request by hand, the branch is no longer rebuilt and newer sources only get a comment there; a changed page of Anthropic's Files reference (hashes in `contracts/sources/anthropic-files.pages.json`) opens an issue, closed by updating the transcription and running the script with `--update-pages`. The `tests` workflow also runs on `labeled`/`unlabeled`, so a `no changelog` label added later reaches the check. Set `NO_MKDOCS_2_WARNING=1` to hide Material's notice about its end of life.

## Tests

- `tests/unit/`, `tests/session/` (`BaseSession` and `SessionFactory` on a fake transport), `tests/integration/` (aiohttp against the local server; `test_close_delimited.py` and `test_upload_attempts.py` use raw socket servers to cut bodies and break upload attempts), `tests/providers/`, `tests/testing/` (the test kit and the shared scenarios on its echo provider), `tests/typing/`, `tests/docs/`.
- `src/aiollm/testing/` is the test kit, public and shipped with the `testing` extra (pytest, pytest-asyncio, pytest-aiohttp, jsonschema; `import aiollm` and `import aiollm.testing` load none of them, `test_public_api.py` checks): the doubles in `doubles.py` (`FakeTransport`, `FakeStreamResponse`, `LocalAPI`, `make_method`, `TEST_TOKEN`, `NOW`), the scripted replies in `recording.py`, the local server `Recorder` in `aiohttp.py` (transport code, never imported from its `__init__.py`) and the fixtures in `plugin.py`, loaded by `pytest_plugins` (never an entry point, since its autouse fixtures change the library's behaviour); it is the top layer, imports no provider and may import the shared layer (its scenarios and echo provider run on it). `tests/conftest.py` only loads it and `pytester`, and names the provider keys to clear. `Recorder` (the local server) answers only what a test scripted with `recorder.reply(...)` or an explicit `recorder.default`; any other request gets a 500 and fails the test at teardown, so a hidden retry or an extra request cannot pass. `no_close_delay` patches only `session.aiohttp._CLOSE_DELAY`, `frozen_now` only `http.headers._now` (the library's one wall-clock read; the transport also times attempts with `time.perf_counter` for its log), the autouse `no_retry_wait` only `session.retry.runner.calculate_wait` (waits 0 s and skips the policy's `backoff`; a test that needs the real wait sets its `side_effect` to `calculate_wait` imported before the patch), and the autouse `no_provider_keys` clears the variables the `provider_key_envs` fixture names (none by default; `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` here).
- The shared scenarios are classes of the test kit, `aiollm.testing.contract` (`GenerationContract`, `FilesContract`, `ClientContract`, each with its `GenerationCase`, `FilesCase`, `ClientCase`; they import pytest, so nothing outside tests imports them): `tests/providers/test_generation_contract.py`, `test_files_contract.py` and `test_provider_clients.py` subclass them once per provider (`TestOpenAIGeneration`, ...), so a new provider adds a case and a subclass to each; `test_<name>_client.py` keeps what is the provider's own. `tests/testing/test_echo_contracts.py` runs them on the echo provider (`aiollm.testing.echo`: an API that exists only on the local server, built from the extension API alone), so the core passes every scenario without a real provider; a provider-specific branch in a scenario becomes a field of its case. `aiollm.testing.wire` holds the schema checks of `test_wire_contracts.py` (`Snapshot`, `naming_problems`, `field_problems`; `jsonschema` is in the `testing` extra).
- `tests/providers/test_wire_contracts.py` checks every provider endpoint against the upstream JSON schemas and examples snapshotted in `tests/providers/contracts/` (request schemas closed, so unknown fields fail). The schemas come from the provider's official OpenAPI file where it publishes one (OpenAI: `openapi.yaml` of `openai/openai-openapi`, read from `OPENAI_OPENAPI`; the endpoint's request, response and stream components with every component they reference under `$defs`, `oneOf` turned into `anyOf` and an `allOf` of objects merged into one), otherwise derived from the types of the provider's official Python SDK, pinned in the `upstream` dependency group (Anthropic Messages: `anthropic`, pinned exactly, the request from the body `Messages.create` sends, the response and stream from `Message` and `RawMessageStreamEvent`, with pydantic's `TypeAdapter`; `test_codegen_pin.py` checks that the pin, the manifest and the script's `ANTHROPIC_VERSION` agree). The examples of those endpoints (`responses.json`, `events.json`) are kept in the repository and added by hand from the providers' documentation or a live run; a refresh never changes them: it lists the ones the new schemas refuse under `rejected` in `manifest.json`, and `test_the_snapshot_has_examples` fails until they are fixed or removed by hand. Endpoints without a stream are an `OpenAPIEndpoints` group of operations read from an OpenAPI file alone (`openai/files` from OpenAI's; `anthropic/files` from `contracts/sources/anthropic-files.openapi.json`, a hand transcription of Anthropic's live API reference with its URLs and retrieval date; it is also the codegen input merged with `--merge`): `request.schema.json` holds one `<Operation>Params` object per operation, `operations.json` how each is sent and what it returns (`test_files_contracts.py` checks the method classes against it), `responses.json` the documented results. A new endpoint adds an `Endpoint` (with an `OpenAPIOperation` where there is an official file, otherwise an `SDKOperation`) and a `Case`, or an `OpenAPIEndpoints` group, to `contracts/update.py`; `OPENAI_OPENAPI=<file> uv run --group upstream python -m tests.providers.contracts.update` refreshes the snapshot. A new SDK version changes the pin, the snapshot and the generated types in one change. Every provider model except the `BaseUnknown` ones sets `__upstream_schema__`, the upstream `$def` it mirrors (an object the file writes inline in a property is named `<Owner>.<property>`, such as `ResponseUsage.input_tokens_details`), and each field is checked against it: a response or event model against the response and stream schemas, a request parameter model against the request schema, both ways (`None` only where it allows `null`, required only where it is; a one-value tag that defaults to its value counts as given); a method field whose type is a `Literal` (the streamed method's `stream`) is the method's own constant and is not.
- `aiollm/testing/extension_api.json` is the extension API: by module, every name a provider package takes from the core; `aiollm.testing.extension.check_extension_api(package)` lists a package's imports outside it. `tests/unit/test_extension_api.py` fails when a provider (the echo one too) imports a name outside it, another provider or a plain `import aiollm...`, when a listed name is gone, and when it lists a name no provider takes; a new name is added to it in the same change, and a listed one is removed or changed only with a Breaking fragment.
- `tests/typing/check_public_api.py` is never run: every `# type: ignore[...]` there marks a line that must stay a type error.
- `tests/docs/test_examples.py` runs every ```` ```python ```` block of `README.md` and `docs/**/*.md` (except the historical `testing-plan.md` and `sse-ndjson-plan.md`). Blocks are found by `title="name.py"` on the fence line; a block without a title, a duplicate title or a title no test runs fails `test_every_example_is_tested`, so a new example needs a title and a test. `tests/docs/test_unification.py` checks that `docs/unification.md` has a row for every field of the shared types and that every error case raises what it names.
- Coverage is kept at 100 % in practice (the configured floor is 98).

Provider schemas are read from their sources, never from a third-party dump: OpenAI's official OpenAPI file, Anthropic's official SDK types and live API reference (<https://platform.claude.com/docs/en/api>). Prices and model lists are checked on the providers' own pages.

## Architecture

The guide pages (`docs/guide/`) describe the behaviour for users; read the code for the details. What follows are the invariants that are easy to break.

- **Request flow.** A `BaseAPIMethod` → `BaseSession.send_request` → (tenacity retry, only if `method.retryable`, by the call's `retry_policy` or else the session's `RetryPolicy`, 4 attempts by default) `_send_once` → transport `_execute` → `BufferedResponse` → `_raise_for_status` → `method.response_parser`. The status check stays inside the retried `_send_once`: the raised error's `transient` flag is the only thing that allows a retry; a policy's `retry_if` can only refuse one, and an error raised by `retry_if` or `backoff` (or an invalid wait) gets the request's error as its `__cause__`, since tenacity would drop it (`session/retry/runner.py`).
- **Stream flow.** `async with session.stream(method)` retries only the opening (`_open_stream_once` → transport `_open_stream` → `IStreamResponse`, ≥ 400 read and raised there), then yields `Stream(method.stream_parser.parse(...))` and closes parser and response on exit, both through `closing_source`, so a failing close (an upload left open) is a note on the error that ended the block, not a replacement. Failures while iterating reach the caller; `Stream` wraps transport errors in `APIStreamInterruptedError`. A declared `__stream_terminal__` makes the parser require it as the last item.
- **Methods** are Pydantic models configured by dunder `ClassVar`s (`__request_path__`, `__request_method__`, `__request_query__`, `__request_body_format__`, `__request_headers__`, `__value_formatter__`, `__retryable__`, `__returning__`, `__response_format__`, `__response_parser__`/`__stream_parser__`, `__stream_terminal__`). The protocols (`methods/protocols.py`) expose only regular properties, never the dunders: putting a dunder `ClassVar` into a protocol breaks pyright's protocol matching. Class-level checks (path template, query fields, body fields, response type vs format) run in `__pydantic_init_subclass__` and raise `TypeError` at class definition; they run on user-declared classes only (`__pydantic_generic_metadata__["origin"] is None`), and an explicit parser skips the format check. Wire names go in `validation_alias`/`serialization_alias`, never `alias`.
- **Optional fields.** A request field without a default is required, `None` is sent as `null`, and a field that defaults to `MISSING` (pydantic's sentinel) is left out of the body and the query. A default of `None` (also from a default factory, called once to see; `defaults_to_none`), or a class of data with one anywhere in a field's type (models, dataclasses, `NamedTuple`, behind `NewType` too; `nested_data_classes` and `none_defaults` in `methods/fields.py`), raises `TypeError` once the class is complete, and so does `MISSING` in a type without the `MISSING` default or the other way round (`names_missing`; `Any` takes it) (`_check_defaults` from `__pydantic_on_complete__`: at definition, or at the first use of a class that names a type defined further down; the message is kept in `__definition_error__` and `model_post_init` raises it for every instance, since Pydantic keeps such a class usable; `exclude=True` fields are skipped), so nested request data is a `TypedDict` or a model whose optional fields default to `MISSING` (the generated provider parameters). The walk remembers models, `TypedDict`s and type aliases, so a recursive alias (`type JSON = dict[str, JSON] | ...`) ends; `guard_traversal` is for values and would raise on a cycle, which is legal in a type. A type with a `PlainSerializer` (`serialized_by_hand`) is not looked into, since the serializer decides what is sent. `get_body_map` dumps without `exclude_none`, so a model put into a body at run time sends `None` as `null` too (a response item goes back as it came only through `model_dump(exclude_unset=True)`). Shared requests (`BaseRequest`) validate assignments; adapters still meet whatever `model_copy` lets past and leave it to the method's validation. The query and the form refuse `None` (`ValueError`); `MISSING` inside a list or a dict raises `ValueError` in the normalizer and the query; a path field cannot default to `MISSING`.
- **Paths.** `request_path` is already percent-encoded (that escaping prevents path injection), so `IAPI.build_url` joins it with `URL.joinpath(..., encoded=True)`; yarl's `/` would double-encode.
- **Sessions.** `BaseSession` holds all transport-neutral logic; a transport implements `_execute`, `_open_stream` and `close()`, returning error statuses as responses and raising `APITransportError` subclasses for I/O failures (mapped in one place, `http/exceptions/aiohttp.py`). `AiohttpSession._request` builds the headers on every request (session < method < call < auth, auth last) and never passes `timeout=None` to aiohttp, which would disable every limit. A session is bound to one event loop (`session/loop.py`), and the `loop` property never binds one.
- **Uploads.** Every attempt has an `AsyncExitStack` (`uploads`): the body builder opens each upload at once and registers its reader with `push_async_exit`, the session adds `wait_for_writer`; the order on exit is release the response, wait for the writer, close the readers (aiohttp neither closes a body iterator it stops writing nor waits for the task it cancels). `types/files.py` holds the lifecycle helpers: `closing_source` (one close rule, a failing close becomes a note on the error that ended the block), `ThreadWork` (blocking calls in a worker thread; a cancelled call runs on, and the resource is released or reused only after it: `finish` is async, runs a blocking cleanup in the thread, never in the loop, and puts it off into a kept task while a call runs; a failure nobody can receive any more is noted on `finish`'s `error` and reported through the loop's exception handler, never dropped and never raised into a later caller) and `open_file`; `_READERS` holds an `IOFile` lease per stream.
- **Errors.** `AIAPIError` (root `exceptions.py`) composes `default_message` + `detail: <message>` and pickles through `__reduce__`. `http/exceptions/` splits by what came back: `APIStatusError` (by status in `HTTP_ERRORS`, or in-band failures below 400, which are never transient), `APITransportError` (no response) and `APIResponseError` (unusable response, never retried). Resolvers (`BaseErrorResolver` and the providers') return errors; `classify` keeps the in-band rule for every resolver.
- **Clients and providers.** `BaseClient` owns its session (also a given one). `BaseProviderClient.__init_subclass__` checks that client, resolver and adapters name one `Provider`. A provider client declares each shared resource as a class attribute made by `bind_resource` (`client/binding.py`): it returns a `ResourceBinding` typed as the resource, like `dataclasses.field`, because pyright does not apply a descriptor's `__get__` when it matches a class against a protocol's property (`IGenerationClient.generation`). `BaseProviderClient.__init__` builds every adapter before the session and every resource after it. A provider package has one `PROVIDER: Final` in its `api.py`.
- **Shared layer.** Adapters (`adapters/`) are pure converters with no session, no I/O and no mutable state that outlives one method call (concurrent calls share an adapter and the shallow copies `with_options` makes; an adapter without options still runs `checked_options(..., NoProviderOptions, ...)`, so no key is dropped); use cases (`resources/usecases.py`) only orchestrate and pass the call's `CallOptions` (`headers`, `timeout`, `retry_policy`, the keyword-only arguments of `ISession.send_request`, kept in step by a test) to the session unchanged; `client.generation` takes them next to the request fields, so no `GenerationRequest` field may be named like one (a test checks); `GenerationResource` is the one generation resource for every provider and checks that a stream ends with exactly one `CompletedEvent`. Provider-only request fields go in `provider_options=` of `create`/`stream`; the resource builds that call's use case on a copy of the adapter (`IGenerationAdapter.with_options`) that merges them into the method's fields. Each provider's options are a `TypedDict` whose keys are method fields of the same type and never a field the shared request fills (`test_provider_options.py`); where a shared field fills part of an object (`effort` → OpenAI's `reasoning.effort`, `output_schema` and `effort` → Anthropic's `output_config`), an option may fill the rest of it with a `TypedDict` of the other keys, and `merge_options` (`adapters/validation.py`) merges them one level deep and refuses a key both set. `IGenerationResource` has no such parameter, so code that works with any provider cannot pass them; the concrete resource still matches it only because `CallOptions` is closed (PEP 728, `typing_extensions` until 3.15): pyright refuses a keyword parameter beside `**options` of an open `TypedDict` when it matches a protocol without it, so `CallOptions` must stay closed. `FilesResource` (`client.files`) is the one files resource, on an `IFilesAdapter` (`BaseFilesAdapter`) that builds the provider's five Files methods: it walks the list's pages itself and refuses a `ProviderFile` of another provider (`RequestValidationError`, field `file`), as `check_files` does for a part's `file` in both generation adapters. `docs/unification.md` lists what every shared field becomes per provider. `client.generation.tool_runner` (`resources/tool_runner.py`, not part of `IGenerationResource`) binds and checks every tool call before any callback runs, then runs the callbacks through aiopulse's `CallbackExecutor` (results in tool-call order unless `in_order=False`, `concurrency` and `buffer_size` passed on, first failure cancels the rest unless `on_error` turns it into the call's output; a callback that is not async runs in a worker thread through `ThreadWork`, so a cancelled one runs on and reports a late failure to the loop); failures are raised as its `CallbackExceptionGroup`, re-exported from `aiollm` with `CallbackFailure` and `CallbackCancelledError`. aiopulse is a runtime dependency, published on PyPI as `aiopulse-py` (the name `aiopulse` belongs to another project) and imported as `aiopulse`.

## Conventions

- Industry standards and the official provider SDKs' behaviour take precedence over local rules, but only where that is logically justified for the library: "the SDK does it" alone is no argument, either way. A conflict is settled with the maintainer.
- A change PR adds a fragment to `CHANGES/` and never bumps the version or edits `CHANGELOG.md`; a release is a separate PR that runs `towncrier build` and bumps `__meta__.py`, the README and this file (`ai-api-release`), so parallel PRs never conflict in the changelog.
- A shared (unified) type holds what every provider has; provider-only data stays in the provider's own types and is reached through `raw`.
- Request fields follow the upstream schema: `None` in the type only where it allows `null`, a `MISSING` default only where the field is optional, no default where it is required (`test_method_fields_match_the_request_schema` checks the provider methods). Shared requests take no `None` (`T | MISSING = MISSING`) and adapters pass the values on unchanged; response types keep `= None`, since they are never sent as requests.
- Packages are layers and sit directly under `aiollm/`, in dependency order: core (`__meta__.py`, `enums.py`, `exceptions.py`) → data (`types/`, `serialization/`) and HTTP primitives (`http/`: API, auth, headers, and `http/exceptions/`) → `methods/` → `response/` → `session/` → `client/` → `adapters/` → `resources/` → `providers/<name>/`. A module imports only from the layers below it; nothing outside `providers/` imports a provider, and the infrastructure (everything but `types/requests/`, `types/responses/`, `adapters/`, `resources/` and `providers/`) never imports that shared layer (`tests/unit/test_layers.py`); the only exception to the order is `methods/base.py`, which imports the default parsers from `response/parse/`, and protocols that refer to each other import under `TYPE_CHECKING`. No package holds a single module, nothing is nested more than three levels below `aiollm/`, and a module is named after its content, never after its package; these layout rules apply where they do not break a package's meaning (a rule that would split or misname what belongs together is reconsidered with the maintainer) (`base.py` holds base classes, `protocols.py` the protocols; `response/X.py` is a kind of response and `response/parse/X.py` its parser).
- Transport-specific code lives only in `<layer>/<transport>.py` modules (today `http/exceptions/aiohttp.py`, `response/aiohttp.py`, `session/aiohttp.py`, `session/body/aiohttp.py`) and is never imported from an `__init__.py`, so the core imports without the transport and a second transport (e.g. httpx) adds `*/httpx.py` files. The only exception is a provider package's `__init__.py`, which re-exports its client and so binds its transport.
- Public imports: every package `__init__.py` re-exports its layer's public names with a sorted `__all__` (`tests/unit/test_public_api.py` checks them, and that `import aiollm` does not load aiohttp), and `aiollm/__init__.py` re-exports what most code needs: method and type base classes, files, enums (`Effort` among them), auth, `BaseAPI`, `Headers`, `Stream`, `ServerSentEvent`, `BaseSession`, `BaseClient`, `BaseProviderClient`, `bind_resource`, `BaseErrorResolver`, the whole error tree, `SessionMismatchWarning`, the retry policy (`RetryPolicy`, `RetryState`, `FullJitterBackoff`) and the shared generation layer (`GenerationRequest`, `Turn`, `NoProviderOptions`, `GenerationResponse`, `TokenUsage`, the events (`ReasoningDeltaEvent` too), `GenerationStream`, `IGenerationAdapter`, `IGenerationResource`, `IGenerationClient`). Internal helpers (`methods/fields.py`, `methods/path.py`, `client/validators.py`, decoders, constants) are not re-exported; the checks of `adapters/validation.py` that adapters run (`checked_options`, `merge_options`, `request_errors`, `check_conversation`, `check_files`) are, from `aiollm.adapters`.
- Naming: a method property is its dunder without underscores (`__request_body_format__` → `request_body_format`), except `__returning__` → `response_type`, kept from the aiogram-style design; stream generics are `ItemT`, buffered ones `ResponseT`; a response argument is named `response`, never `buffered`; module-level constants are `Final` and upper case (callables such as `session_factory` stay lower case); a helper with no callers outside its module starts with `_`; shared header names and media types are constants in `http/headers.py` (a header of one provider, such as `ANTHROPIC_VERSION`, is in its `api.py`); enums are compared with `is` and providers with `==`; constructor arguments after the required collaborators are keyword-only.
- A provider is a flat package: `providers/<name>/api.py` (its `IAPI`), `resolver.py` (its error resolver) and `client.py` (client and session factory); `types/`, `methods/` and `adapters/` subpackages come with its first endpoints, and its resources build `AdapterUseCase`s from those adapters. The response and event types (`types/<family>.py`) and the request parameters (`methods/params/`) are generated by aiollm-codegen through `scripts/generate_provider_types.py` and never edited by hand (OpenAI from its official OpenAPI file, Anthropic from the SDK-derived Messages snapshot plus the transcribed Files reference). Both inputs are pinned: the generator is the `codegen` dependency group, a commit of `aiollm-org/aiollm_codegen` in `pyproject.toml` and `uv.lock` (`--codegen DIR` runs a local checkout to try a change), and OpenAI's file is `OPENAI_OPENAPI_URL` at a commit of `openai/openai-openapi`, checked against `OPENAI_OPENAPI_SHA256`, the hash of the contract snapshot's file (`test_codegen_pin.py`); a new file changes the snapshot and the pin together; `types/options.py`, the method classes in `methods/<endpoint>.py` (retries, parsers, terminals, the limits a schema leaves out) and the adapters stay hand-written. `methods/params/` is four levels below `aiollm/`: the parameters are the methods' own fields, so the depth rule gives way (decided with the maintainer, 2026-11-06).
- Every module, class, function and method (including private ones and protocol members) has a Google-style docstring (`Args:`, `Returns:`, `Yields:`, `Raises:`, `Attributes:`, `Example:`). Ruff enforces this (`D` rules, `convention = "google"` in `pyproject.toml`), so `uv run ruff check src` fails on missing or malformed docstrings.
- Uses modern syntax that Python 3.13 supports: PEP 695 generics (`class Foo[T]`, `def parse[T]`, `type X = ...`) and PEP 696 defaults (`[SessionT: ISession = ISession]`). Every module starts with `from __future__ import annotations` (ruff's `required-imports` adds it), so names imported under `TYPE_CHECKING` and forward references are used unquoted in annotations; 3.13 has no deferred evaluation of its own (PEP 649 is 3.14). Do not use 3.14+ syntax or stdlib APIs, such as `except A, B:` without parentheses (PEP 758).
- A provider type uses `Literal` for a schema constant that names the object (`type`, `object`, `role: "assistant"`) and `str` for an enumeration that grows (`status`, `stop_reason`, error codes), so a new value of the latter does not fail a whole response.
- `Provider` is an open value, a `str` subclass (`enums.py`) whose pydantic fields take a non-empty string: the core declares only `Provider.GENERIC`, and every provider package, in the library or outside it, its own `PROVIDER: Final = Provider("<name>")` in `api.py`, so files and errors of two third-party providers stay apart.
- Ruff rule set is broad (pylint, bugbear, simplify, logging, etc.); `print` is disallowed (T20), naive datetimes are flagged (DTZ), and log calls take lazy `%` arguments, never f-strings (G).
- Logging: only a module that logs has `logger = logging.getLogger(__name__)` (add it with the first call); `aiollm/__init__.py` only adds a `NullHandler` to `aiollm`. An exception that reaches the caller is never logged (no `logger.error` before `raise`: 400/401/404, exhausted retries, parse errors, `CancelledError`, a close error added as a note). What the library handles or swallows is: a retry at WARNING (the failed attempt's error type and how many notes it has), a recovered or deliberately suppressed error at DEBUG (by its type, never its message, notes or traceback), details of a call at DEBUG; INFO only for a significant success. A failure no caller can receive goes through `ThreadWork`'s `_report` to the loop's exception handler only, never also `logger.exception`. Each layer logs only its own part: `session.base` a call's start, end and retries, the transport each attempt (sent, with the declared `request_path_template`; finished with status and duration). Never log, at any level, tokens, keys, headers, bodies, query strings, the values of path parameters, an error's message, notes or traceback, or file names (the official SDKs log bodies at DEBUG; we do not, prompts are personal data), and add no env var that configures logging. The records are listed in `docs/guide/sessions.md` and checked by `tests/integration/test_logging.py`.
